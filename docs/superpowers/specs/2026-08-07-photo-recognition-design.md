# 拍照识别物品设计（Android 内测版先行）

日期：2026-08-07

## 背景

用户希望在 App 中加入「拍照识别物品」功能：拍照后由 AI 自动识别物品名称并填入新增物品表单，过期日单独拍一张照片识别。该功能属于既有真源的范围变更（`dev-docs/project-brief.md` 原写明「第一版不做照片上传、AI 图片识别」），经用户逐项确认后纳入 Android 内测版阶段范围。

用户的核心顾虑是服务器存储与流量成本。经讨论确认：只保存几 KB 的物品缩略图，不保存原图；识别瞬间照片会发送给第三方 AI 服务商，识别后即弃。

## 已确认决策

| 决策点 | 结论 |
| --- | --- |
| 功能形态 | 拍物品正面照 → AI 识别名称自动填表；可选拍有效期照片 → AI 读日期填过期日 |
| 照片存储 | 只保存缩略图（160–200px，约 5–15KB），原图识别后即弃 |
| AI 服务 | 火山引擎豆包视觉（Doubao Vision），API key 仅存服务器环境变量 |
| 识别链路 | 方案 A：Android 本地压缩（约 1280px、200–400KB）→ 上传服务器 → 服务器生成缩略图暂存 + 调豆包识别 → 返回名称/日期与缩略图暂存 id → 用户确认保存时关联 |
| 图片存储 | 第一版存服务器本地磁盘，代码留存储抽象层，后续可切 OSS |
| 实施端 | Android 内测版先行，Web/PWA 后续 |
| 成本 | 单次识别约 0.005–0.02 元；用户确认可接受 |

## 用户流程

```text
新增物品 -> 点「拍照识别」
  -> 拍物品正面照（或从相册选一张）
  -> 上传识别 -> 表单自动填入物品名称，显示缩略图预览
  -> （可选）点「拍摄有效期」-> 拍背面/瓶底照片 -> AI 读日期 -> 自动填入过期日
  -> 用户补全位置、备注 -> 保存 -> 物品带上缩略图
```

- 有效期照片只用于识别，不保存。
- 识别失败或网络异常时提示用户，可重拍或手动输入，不阻塞建档。

## 服务器架构

### 识别接口 POST /api/recognition

请求：multipart 图片 + 模式字段（`mode=name` | `mode=expiry`）。

处理流程：

1. 校验登录 session，解析当前用户与默认/当前家庭。
2. 图片大小与类型校验（拒绝超大文件，防止滥用）。
3. `mode=name`：生成缩略图（160–200px）写入待关联区，记录 `pending_photos`（归属家庭、创建人、创建时间）；把上传图压缩到约 1280px 发给豆包识别名称。
4. `mode=expiry`：不生成缩略图暂存，直接把图压缩到 1280px 发给豆包读取有效期。
5. 返回：`{ mode, name? / expireDate?, thumbnailId? }`。

豆包调用失败、超时或识别结果明显不可用时返回明确的失败原因，前端走手动输入兜底，不把失败当成功。

### 保存物品时关联缩略图

- 现有物品创建接口（`POST /api/inventory/items`）新增可选字段 `photoKey`。
- 服务器校验：该缩略图由当前用户创建、归属当前用户家庭、尚未被关联、未过期；成功后把 `items.photo_key` 指向该文件，并把 `pending_photos` 记录置为 `attached`。
- 一个缩略图只能关联一次；关联失败不阻塞物品保存（物品可以先建，图可以后续补）。

### 图片读取 GET /api/inventory/items/:id/photo

- 必须登录；服务端校验当前用户是物品所属家庭的成员，否则返回 403/404。
- 返回缩略图文件（体积小，可加缓存头）。
- 不允许公开静态访问，避免绕过权限。

### 孤儿清理

- 定时或惰性清理：删除 `created_at` 超过 24 小时仍未关联的 `pending_photos` 记录及其文件。

### 频率限制

- 每账号每分钟识别次数上限（初值建议 5–10 次），超限返回 429，防止刷豆包额度。

## 数据模型变化

### items 新增列

```text
photo_key text  -- 缩略图文件名，可空，唯一
```

### 新增 pending_photos 表

```text
id            uuid pk
household_id  uuid not null references households
photo_key     text not null unique
created_by    uuid not null references users
created_at    timestamptz not null default now()
status        text not null default 'pending'  -- pending | attached
```

- 只有创建人（且归属家庭）能读取/使用自己的 pending 记录；关联动作在服务端校验创建人与归属家庭。
- Supabase 参考路线用 RLS，自托管路线用服务端校验，语义一致。

## Android 端设计

- 新增物品弹窗加入「拍照识别」入口与「拍摄有效期」入口。
- 拍照用系统相机（`ACTION_IMAGE_CAPTURE` + FileProvider）；相册用 Android Photo Picker（无需存储权限）。
- 拍照/选图后在本地压缩到约 1280px（JPEG/WebP 中等质量，200–400KB）再上传。
- 上传识别成功：名称/日期回填表单；缩略图预览展示识别所用的照片压缩图。
- 保存物品时携带 `photoKey`；保存成功后物品列表展示缩略图。
- 网络失败/识别失败：表单保留已填内容，提示重试或手动输入；不写入任何失败状态。

## 安全与合规

- 豆包 API key 只存在于服务器环境变量，App 与前端永不接触。
- 图片访问必须登录且是物品所属家庭成员；不能只靠前端隐藏入口。
- 识别请求携带的照片会瞬时发送到火山引擎，公开推广前必须在隐私政策中写明。
- 识别接口频率限制；图片上传大小限制；pending 记录隔离与过期清理。

## 测试与验收

服务器端（TDD）：

- 识别服务单测：mock 豆包返回名称/日期/失败/超时。
- 权限负例：用户 B 不能读取用户 A 的 pending 缩略图或物品照片；B 不能把 A 的 `photoKey` 关联到自己的物品。
- 孤儿清理：超时未关联的缩略图与文件被删除；已关联的不删。
- 频率限制：超限返回 429。

Android 端：

- 本地压缩尺寸/体积测试。
- 识别成功回填、失败兜底、网络异常提示。
- 保存携带 `photoKey`、列表显示缩略图。

真机验收：

- 拍一件物品 → 名称自动填、缩略图显示、过期日单独识别成功。
- 断网/识别失败时不崩溃，可手动输入保存。
- 家庭成员能看到共享家庭物品的缩略图；被移除成员不能访问。

## 本阶段不做

- Web/PWA 端拍照识别（Android 先行，Web 后续）。
- 高清原图保存、多图附件。
- OSS 接入（预留存储抽象层，数据量上来后再切）。
- 扫码识别、iOS。
