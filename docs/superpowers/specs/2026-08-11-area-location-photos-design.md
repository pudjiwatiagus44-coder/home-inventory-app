# 区域/位置照片功能设计

日期：2026-08-11

## 背景

用户希望在区域、位置上保存照片，用来快速回忆“这个位置长什么样、这一区放了什么”。现有 App 已经有物品缩略图照片链路，但区域和位置没有照片能力。

本次设计范围是 Web/PWA 与 Android 内测版一起实施：每个区域、每个位置各保存一张主照片；物品行里把位置名（如 `A1`）和区域名（如 `客厅`）做成小按钮，点击分别查看位置照片和区域照片。

## 已确认决策

| 决策点 | 结论 |
| --- | --- |
| 实施端 | Web/PWA 与 Android 内测版一起 |
| 照片对象 | 区域一张、位置一张，均为单张主照片，可替换 |
| 清晰度/存储 | 服务器保存约 1280px、100–300KB 的清晰图，用于 Web/Android 全端查看 |
| 上传方式 | 拍摄或从相册选择，上传压缩后保存 |
| 保存时机 | 拍照/选图后立即上传，上传成功才保存；不支持断网离线队列上传 |
| 查看入口 | 物品行里位置名、区域名显示为小按钮；长按区域/位置编辑弹窗里也能查看/替换/删除 |
| 无照片提示 | 点击无照片按钮时提示“拍照或从相册选择” |
| 缓存 | Android 本地缓存一张清晰图，Web 用浏览器缓存；本地有图优先看本地，没有才联网 |
| 权限 | owner/member 可拍摄、替换、删除；readonly 只能查看，服务端强制 |
| 数据模型 | `areas`、`locations` 各新增 `photo_key` |
| 图片存储 | 第一版继续存服务器本地磁盘（现有 `PhotoStore`），后续可切 OSS |
| 实施路线 | 先写设计文档，用户审阅后进入实施计划，不直接改功能代码 |

## 用户流程

```text
长按区域/位置
  -> 打开编辑弹窗，弹窗内新增照片区
  -> 没照片：点“拍照”或“从相册选择”
  -> 有照片：可查看、替换、删除
  -> 照片上传成功后刷新区域/位置照片状态

点击物品行里的 A1 / 客厅 小按钮
  -> 有照片：打开照片查看器，本地缓存优先，缺失再联网
  -> 没照片：提示“还没有位置/区域照片，拍照或从相册选择”
  -> 完成拍摄/选图后自动上传并保存
```

## 产品与界面

### 长按区域/位置

- Android：长按区域/位置沿用现有编辑弹窗，弹窗内新增照片区。
- 没照片时显示“拍照”“从相册选择”两个动作。
- 有照片时显示当前照片缩略图，以及“查看”“替换”“删除”动作。
- Web 移动端同样支持长按；Web 桌面端通过区域/位置卡片上的照片入口和编辑弹窗完成相同操作。
- readonly 成员不显示拍摄、替换、删除动作。

### 物品行小按钮

- 物品行内，位置名和区域名显示成小按钮，并排在物品名称下方，例如 `A1`、`客厅`。
- 点击位置按钮查看位置照片；点击区域按钮查看区域照片。
- 未分配位置或未选区域的物品不显示对应按钮。
- 备注仍按现有方式显示，不因小按钮消失。

### 照片查看器

- Android 复用现有 `PhotoPreviewDialog` 的查看体验。
- Web 使用浏览器图片查看弹层。
- 查看时本地缓存优先，缺失再联网拉取。

## 数据与存储

- `areas` 新增 `photo_key text`，可空、唯一；唯一索引仅作用于非空值。
- `locations` 新增 `photo_key text`，可空、唯一；唯一索引仅作用于非空值。
- 照片文件沿用 `PhotoStore` 存储抽象，第一版存服务器本地磁盘。
- 区域/位置照片不走 `pending_photos` 暂存：上传后直接压缩、保存文件、写入 `photo_key` 并返回。物品照片的 `pending_photos` 流程保持不变。
- Dashboard/Snapshot 返回数据中给区域、位置都增加 `photoKey`，前端据此判断有图/无图。

## 接口设计

### PUT /api/inventory/areas/[areaId]/photo

- 请求：multipart 图片。
- 权限：登录、家庭成员、可写成员（owner/member）。
- 流程：校验图片类型和大小 -> 压缩到约 1280px -> 保存新文件 -> 更新 `areas.photo_key` -> 若已有旧照片则删除旧文件 -> 返回 `{ ok, photoKey }`。
- 原始图片限 JPEG/PNG/WebP、不超过 10MB；压缩后保存约 1280px、100–300KB。
- 替换照片时，旧文件只在新文件保存成功且数据库更新成功后删除。

### GET /api/inventory/areas/[areaId]/photo

- 权限：登录、家庭成员（含 readonly）。
- 返回图片文件，带缓存头供 Web 浏览器缓存。
- 照片不存在返回 404。

### DELETE /api/inventory/areas/[areaId]/photo

- 权限：登录、家庭成员、可写成员。
- 清空 `areas.photo_key` 并删除文件。

位置使用同一套接口：`locations/[locationId]/photo`。

删除区域/位置时，服务端先删除数据库记录，再清理该对象及关联位置的照片文件；文件清理失败不阻塞数据库删除，记录日志由后续清理兜底。

## Android 端设计

- Room 的 `AreaEntity`、`LocationEntity`、DTO 和 `InventorySnapshot` 增加 `photoKey`。
- 长按编辑弹窗增加照片区，复用现有相机（`TakePicture` + FileProvider）和相册选择器。
- 上传前本地压缩到约 1280px、JPEG 中等质量。
- `LocalPhotoStore` 按 `photoKey` 缓存清晰图；查看时本地优先，缺失回退服务器。
- 照片上传、替换、删除必须联网；断网时提示“需要网络”，不进入离线队列。
- 物品行小按钮用现有 Compose 样式实现，点击不触发物品编辑。

## Web/PWA 端设计

- Dashboard 数据类型增加区域、位置的 `photoKey`。
- 物品行里渲染位置/区域小按钮；区域栏、位置栏卡片提供照片入口。
- 编辑弹窗增加照片区，移动端使用带 `capture` 的 `input[type=file]` 调起相机，桌面端走文件选择。
- 查看优先依赖浏览器缓存；接口返回 `Cache-Control` 缓存头。

## 权限与安全

- 照片读取必须登录且是照片所属家庭成员，readonly 可读。
- 照片写入必须登录且是家庭成员，readonly 被服务端拒绝（403），不只依赖前端隐藏按钮。
- 用户 A/B 越权读取或写入照片均返回 403/404。
- 上传图片限制类型与大小，防止超大文件占用存储。
- 新增接口按账号限频（初值 20 次/小时），超限返回 429，防止滥用。

## 错误处理

| 场景 | 处理 |
| --- | --- |
| 未登录 | 401 |
| 非家庭成员 / 对象不存在 | 403/404 |
| readonly 写入 | 403 |
| 图片类型不支持 / 文件过大 | 400 明确提示 |
| 超出照片接口限频 | 429 |
| 网络中断 / 上传失败 | 保留表单，提示重试，不保存半成品 |
| 替换时旧文件删除失败 | 数据库已更新成功，记录日志，后续清理兜底 |

## 测试与验收

### 服务端

- 上传/替换/删除/读取照片的成功路径。
- 用户 A/B 越权负例。
- readonly 可读、写入被拒。
- 替换和删除后旧文件被清理。
- 删除区域/位置时关联照片文件被清理。
- 图片格式/大小校验。

### Android

- `photoKey` 字段同步与展示。
- 拍照/相册上传、替换、删除。
- 本地缓存优先、缺失联网回退。
- 无照片点击提示。
- 断网提示。

### Web/PWA

- 物品行小按钮渲染与点击。
- 无照片提示。
- 编辑弹窗照片动作。
- 上传请求与缓存行为。

### 手工验收

- Android 真机拍照、相册选图、替换、删除。
- Web 手机和桌面端查看/上传。
- 家人共享成员可查看；被移除成员无法访问。

## 本阶段不做

- 多张照片图集。
- 照片离线队列上传。
- 区域/位置照片 AI 识别或自动分类。
- 高清原图保存。
- 视频。
