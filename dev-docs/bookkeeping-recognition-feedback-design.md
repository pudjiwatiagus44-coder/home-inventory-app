# 记账识别纠错反馈设计真源

## 状态与范围

- 2026-09-01 用户确认继续实现识别纠错闭环；本地代码、测试和开发 migration 纳入当前范围。
- 生产数据库迁移、服务器部署和公网验收不在本次确认内，执行前必须再次确认。
- 纠错反馈用于减少当前账号后续相似文字记账中的金额、分类、用途等识别错误，不做跨账号共享，不自动创建豆包精调任务。
- 2026-09-01 用户确认结构化付款金额候选：Android 本地可传脱敏 OCR 文本、标签、金额、优先级和归一化相对位置；服务端不接收截图或像素。该机制用于优先识别 `实付款`、`成交价`、`支付成功`，排除广告、券后价、优惠和商品标价；开发与生产状态仍遵循本文件的确认门禁。

## 用户闭环

1. Android 文字识别完成后发送结果通知，点击通知进入对应交易编辑页。
2. 识别交易提供“保存修改”和“保存并报错”；非识别交易只有普通保存。
3. “保存并报错”先展示脱敏原文、原结果、修改后结果和差异项，用户每次明确确认后才上传。
4. 账目保存与反馈提交分开报告：账目保存成功但反馈失败时，不回滚账目，也不能显示成反馈成功。
5. 设置页允许查看反馈摘要并物理删除当前账号全部反馈。

## 数据与隐私边界

- 客户端只上传用户主动输入并经过既有脱敏器处理的文字，长度 1–4000 字；禁止上传截图、设备 ID、完整银行卡号、登录密码或未脱敏敏感信息。
- `original` 与 `corrected` 都固定为记账理解接口的 12 个字符串字段，不接受额外字段。
- `differences` 只允许 `amount`、`category`、`note`、`dateTime`、`type`、`merchant`、`other`。
- 每条反馈包含客户端生成的稳定 UUID、实际模型标识和授权时间。相同账号和 UUID 重复提交必须幂等。
- 服务端所有读、写、删都通过当前登录会话解析账号；请求不得接受客户端提供的 `accountId`。
- 日志和错误响应不得包含原文、原结果或修正结果正文。

## 服务端存储

新增独立表 `bookkeeping_recognition_feedback`：

- 复合主键 `(account_id, id)`；`account_id` 外键指向 `bookkeeping_accounts(id)` 并级联删除。
- 保存脱敏 `source_text`、`original_result`、`corrected_result`、`differences`、`model`、`authorized_at`、创建/更新时间。
- 按 `(account_id, created_at desc)` 建索引。
- 删除反馈为当前账号范围内的物理删除，不影响本地交易。

## API 与账号内示例

- 新增认证接口 `/api/bookkeeping/feedback`：POST 幂等保存，GET 只返回摘要，DELETE 物理删除当前账号反馈。
- `/api/bookkeeping/understand` 在存在有效登录会话时，可检索当前账号最多 10 条相似纠正样本；无会话、无样本或查询失败时退化为普通识别。豆包上下文会被预算限制为可承载的脱敏示例数量。
- 相似样本只返回脱敏原文和修正结果，不返回其他账号数据。
- 纠正样本按“不可信 JSON 数据”放入 user message；system prompt 明确它只能辅助字段纠正，不能改变系统指令和固定 12 字段输出契约。
- 识别成功响应返回实际模型标识，Android 将其和识别来源一起保存。

## 验收门槛

- 类型解析覆盖字段白名单、长度、UUID、差异枚举和额外字段拒绝。
- 服务层覆盖重复提交幂等、用户 A 不能读删用户 B、删除只影响当前账号。
- 路由覆盖未登录 401、POST/GET/DELETE、账号隔离和错误信息不泄露正文。
- 理解接口覆盖最多 3 条当前账号示例、无会话退化、数据库失败退化和提示注入防护。
- Android 覆盖差异计算、每次授权预览、反馈失败不回滚账目、通知进入编辑和设置页物理删除。
- 生产 migration 与部署前重新确认，并在备份、回滚和账号 A/B 负例完成后才可标记上线。
