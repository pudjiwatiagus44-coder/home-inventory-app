# 记账文字识别与分类协议真源

## 范围

Android 本地记账 App 通过用户主动输入的文字调用 `POST /api/bookkeeping/understand`。服务端只接收文字和必要分类上下文，不接收、保存或转发截图，也不做后台监听。

## 文字批量识别

- 请求包含 `ocrText`、`capturedAt` 和可选的 `categories` 分类上下文。
- 一次请求允许多笔交易；响应是结构化数组，每笔包含日期时间、收支类型、金额、币种、类别及可选商家、账户、参与人、标签、项目和备注。
- 服务端只负责识别与归类，不写入账本；Android 对每笔结果单独校验、入本地数据库并发送通知。
- 模型失败、超时、响应 JSON 不合法或单笔字段不合法时必须返回明确错误/可定位失败项，禁止伪造成功。

## 分类同步

- 分类是账本级数据，支持父分类/子分类、描述、关键词、图标、颜色、内置标记和启用状态。
- `localId` 仅用于客户端幂等同步；服务端 `id` 是同步后的稳定标识。
- 同步先处理父分类，再处理子分类；子分类缺少父分类映射时拒绝该操作并返回可诊断错误。
- 内置分类不能物理删除，只能停用或恢复默认；用户分类可停用或删除。名称、描述、关键词和展示字段可编辑。
- 当前只更新本地代码、测试和自托管开发 schema；生产数据库 migration、生产部署和公网开放保持 `未验证`，需单独确认。

## 验收证据

- 先通过服务端相关 Vitest 与 `npm run build`，再进行 Android 联调。
- 必须覆盖：单笔/多笔、部分失败、分类上下文、父子分类同步、重复同步幂等、通知成功与失败反馈。
