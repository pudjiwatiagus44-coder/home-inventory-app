# Mainland Production Route Stage

## 阶段目标

把 Home Inventory App 从当前 Vercel + Supabase 临时测试版，推进到面向中国大陆用户的正式 Web/PWA 部署路线。

本阶段不是立即写代码迁移，而是先完成中国大陆正式版的产品、合规、架构和实施拆分。

## 阶段边界

本阶段要做：

- 选择中国大陆云平台。
- 规划域名、ICP备案和公安联网备案。
- 规划国内云服务器或云应用托管。
- 规划国内 PostgreSQL。
- 规划从 Supabase Auth 迁移到自有认证/权限层。
- 规划从 Supabase Postgres/RLS 迁移到国内 PostgreSQL + 服务端权限校验。
- 规划生产环境变量、密钥、日志、备份和回滚。

本阶段不做：

- 不接入短信登录。
- 不接入支付。
- 不上传照片。
- 不做扫码识别。
- 不做家庭成员共享。
- 不做原生 App。
- 不把未备案域名或 Vercel preview URL 当成中国大陆正式生产地址。

## 架构迁移任务

### 1. 阿里云账号、域名与备案

- 确认阿里云账号已完成个人实名认证。
- 确认 `homestorag.xyz` 已完成域名实名认证，且实名主体和个人备案主体一致。
- 购买符合阿里云 ICP 备案要求的中国大陆云资源。
- 通过阿里云 ICP 备案系统发起个人网站备案。

### 2. 数据库迁移设计

- 将 Supabase migration 转换为标准 PostgreSQL migration。
- 去除或替换 Supabase 专属 Auth/RLS 依赖。
- 保留 `profiles`、`households`、`household_members`、`areas`、`locations`、`items` 的业务模型。
- 设计备份和恢复流程。

### 3. 认证迁移设计

- 保留邮箱 + 密码登录。
- 密码只能使用成熟哈希算法保存，不能明文保存。
- 设计 session/cookie 生命周期。
- 设计注册、登录、退出、错误登录、未登录访问拦截。
- 密码重置在第一阶段可暂缓，但必须明确用户无法找回密码的风险；正式公开前应补齐。

### 4. 权限迁移设计

- 所有读写都必须经过服务端权限校验。
- 用户只能访问自己所属 household 的数据。
- 不能只靠前端隐藏按钮。
- 必须保留用户 A/B 权限负例测试。

### 5. 部署与运维设计

- 生产环境变量只放云平台或服务器环境中。
- 数据库密码、JWT/session secret、邮件服务密钥不能进入 Git。
- 应用需要 HTTPS。
- 需要基础错误日志和访问日志。
- 需要数据库备份和恢复演练。

## 验收路径

```text
完成域名和备案
  -> 部署中国大陆正式环境
  -> 打开生产域名
  -> 未登录访问 /app 被拦截
  -> 注册用户 A
  -> 新增区域/位置/物品
  -> 刷新后数据仍存在
  -> 注册用户 B
  -> 用户 B 不能读取、修改或删除用户 A 的数据
  -> 通过中国大陆网络访问速度和可用性检查
```
