# Project Brief

## 项目边界

- 项目名称：Home Inventory App。
- 中文名称：家庭物品管理应用。
- 项目是什么：一个面向普通家庭用户的云端 Web/PWA 应用，用户注册登录后可以记录、搜索、编辑和删除自己的家庭物品。
- 项目不是什么：不是当前局域网单 JSON 本地版的直接改造；不是第一阶段就做原生 App、多人协作、照片上传、扫码识别或会员付费。
- 第一批用户：希望用手机或电脑管理家中物品位置、备注和过期日的个人用户。
- 使用场景：用户想知道某个物品放在哪里、某个位置有什么物品、哪些物品快过期。
- 一句话定位：给每个家庭一个可搜索、可维护、可长期保存的云端物品清单。
- 交付对象：未来公开用户；当前阶段先做 MVP 原型。

## 用户问题和价值

- 用户痛点：家中小物品、药品、食品、工具和备件散落在不同位置，时间久了找不到、忘记过期、重复购买。
- 为什么值得做：当前本地版已经证明“位置 + 物品 + 搜索 + 过期提醒”是有效核心模型，云端版可以让更多用户直接使用。
- 参考来源：当前本地版置物管理系统的数据模型和使用体验。
- 可以学习的地方：格子/区域管理、搜索、过期提醒、移动端优先。
- 不能照搬的地方：单 JSON 文件、局域网可信环境、无账号假设。
- 差异点：第一版专注低成本记录和快速查找，不追求复杂家庭资产管理、装修库存或企业仓储。

## 第一闭环

```text
用户注册/登录
  -> 创建第一个位置
  -> 新增一个物品
  -> 搜索该物品或按位置查看
  -> 编辑/删除物品
  -> 数据保存到该用户自己的云端空间
```

- 第一闭环输入：邮箱、密码、位置名称、物品名称、备注、过期日。
- 第一闭环输出：用户只能看到自己的位置和物品，并能搜索查询。
- 用户可见成功标准：刷新浏览器或换设备登录后，自己的物品仍然存在。
- 失败时用户会看到：登录失败、保存失败、权限不足、网络异常等明确提示。

## MVP 范围

第一版必须有：

- 邮箱 + 密码注册登录。
- 登录用户私有数据隔离。
- 位置管理：新增、编辑、删除、排序暂不要求。
- 物品管理：新增、编辑、删除。
- 搜索物品。
- 按位置查看物品。
- 过期日字段和基础过期提示。
- 响应式 Web/PWA 基础体验。

第一版可以没有：

- 家庭成员共享。
- 物品照片上传。
- 扫码识别。
- AI 图片识别。
- 会员付费。
- 原生 iOS/Android。
- 管理员后台。
- 多语言。

后续再做：

- household 家庭空间与成员邀请。
- 照片和附件。
- 条码/二维码扫描。
- 到期通知。
- 导入当前本地版 JSON 数据。
- 付费会员和容量限制。

## 不做什么

- 第一阶段明确不做手机号短信登录。
- 第一阶段明确不做家庭共享。
- 第一阶段明确不做图片上传。
- 第一阶段明确不做真实支付。
- 第一阶段明确不做原生 App。
- 不把当前本地版 `server.py + shared_data.json` 强行迁移成多用户架构。

## 关键风险

- 登录/权限：用户数据必须按账号隔离，后端/数据库权限必须兜底。
- 支付/会员：第一版不做，仅预留未来边界。
- 上传/文件/隐私：第一版不上传照片，降低隐私和存储复杂度。
- 第三方 API/SDK：Supabase 是核心第三方依赖，必须使用官方文档和安全推荐。
- 生产环境/真实用户：上线前必须补齐隐私政策、数据删除、备份恢复和监控。

## 验收标准

- 用户可以注册、登录、退出。
- 用户 A 创建的物品，用户 B 无法读取、修改或删除。
- 用户新增物品后刷新页面仍存在。
- 用户可以搜索物品并看到正确位置。
- 用户可以设置过期日并看到基础提醒。
- 所有真实数据来自 Supabase，不使用 mock 数据冒充完成。

## 停止条件

- 尚未完成数据库 schema 和 RLS 策略设计，不进入功能开发。
- 尚未确认 Supabase 项目和环境变量管理方式，不接入真实云服务。
- 尚未完成权限负例验证，不声明 MVP 安全可用。

## 2026-08-04 Excel 批量备份与导入规则

- Excel 批量备份与批量导入作为上线后清单维护能力纳入当前 Web/PWA 产品范围。
- 备份和导入均使用 `物品清单` 工作表，表头为 `序号 / 名称 / 格子编号 / 所在区域 / 备注 / 有效期`，兼容参考文件 `物品清单_2026-08-03_17-02-39.xlsx`。
- 备份文件名使用 `物品清单_YYYY-MM-DD_HH-mm-ss.xlsx`。
- 导入必须先预检，不直接写入数据库。
- 预检以 `所在区域 + 格子编号 + 名称` 作为同格同名物品判断键。
- 有效期支持 `YYYY-MM-DD` 和 `YYYY-MM`；当 Excel 只有年月、没有日单位时，默认按该月 1 号导入。
- 如果同格同名物品的备注和有效期也完全相同，自动跳过。
- 如果同格同名物品的备注或有效期不同，弹窗展示当前数据与 Excel 数据对比，由用户选择跳过、都保留或覆盖。
- 全新物品自动导入；缺失的区域和格子由导入流程自动创建。
- 覆盖只更新已有物品的备注和有效期，不改变名称、区域或格子。
- 导入完成后显示新增物品数、覆盖数、保留重复数、跳过数、新增区域数、新增格子数和失败行。

## 2026-08-04 Android 原生内测版规划

- 用户已确认新增 Android 原生 App 产品线：先做 Android 内测 APK，后续再单独规划 iOS。
- Android 第一阶段采用 Kotlin 原生实现，不采用 React Native/Expo，也不采用 WebView 套壳。
- Android 内测版复用现有邮箱 + 密码账号、后端 session、库存 API 和权限边界；不单独建立移动端账号系统。
- Android 内测版包含离线缓存与离线编辑能力：最近一次同步后的清单可离线查看，离线时可新增、编辑、删除区域、位置和物品。
- 离线新增在网络恢复后应自动尽快同步到服务器；同步成功后用服务器返回的真实 id 和更新时间替换本地临时状态。
- 离线编辑和删除采用服务器优先冲突策略：如果服务器数据已变化，Android 不自动覆盖服务器，而是提示用户刷新后重新确认。
- 本阶段仍不加入照片上传、扫码识别、AI 识别、推送通知、家庭共享、支付、管理员后台、应用商店上架或 iOS 实现。
