# 记账 DeepSeek 加密托管与自由分类设计

## 状态

2026-09-22：本地实现与测试完成，并经用户明确确认后部署到 `homestorag.xyz`。生产数据库迁移、加密主密钥、受保护接口和端到端保存/删除 smoke 已验证；真实用户 Key 的上游连通性仍由用户在 App 内自行验证。

## 范围

本设计只在 `bookkeeping_*` 命名空间及记账识别路由中生效，不改库存、家庭、认证核心数据或其 API 行为。

1. 用户可在 Android 端手动选择豆包或 DeepSeek。
2. DeepSeek API Key 由当前登录账号通过 HTTPS 提交，服务器加密托管，供同账号设备调用。
3. 模型不接收分类候选列表，自行返回 `type`（收入/支出）和细分类 `category`；分类名称建议四字内而非硬限制。
4. 重新识别接受旧三字段与新版层级分类合同；文本失败后只用当前已选模型自动进行一次视觉重试。

## 数据与安全边界

新增表 `bookkeeping_deepseek_credentials`，以 `user_id` 为唯一键，字段只包含：版本号、AES-256-GCM 密文、随机 nonce、认证 tag、掩码后缀、最后验证时间和审计时间。禁止存储明文 Key。

- 加密主密钥仅在服务器受限环境变量 `BOOKKEEPING_CREDENTIAL_MASTER_KEY` 中保存，不进 Git、测试输出、HTTP 响应、日志、数据库导出或客户端同步协议。
- 保存、查询状态、验证、更新、删除一律从当前 `home_inventory_session` 推导用户；禁止信任客户端传来的 user ID。
- 状态接口仅返回 `configured`、掩码和最后验证状态，永不返回明文；删除物理删除该账号密文和元数据。
- 服务器只在实际调用 `https://api.deepseek.com` 时于进程内短暂解密；API 模型固定 `deepseek-flash`，采用非思考模式与 JSON 输出。
- 任何 DeepSeek 错误只返回脱敏错误码/HTTP 类别。不得把 Key 或 OCR、截图内容放进普通日志。

## 隐私与调用

默认模型仍为豆包。用户切换为 DeepSeek 前，Android 必须提示：仅用户主动触发的截图会在首次失败的视觉重试中发送至 DeepSeek；不进行后台截图、监听或跨模型自动兜底。

首次识别优先发送本地 OCR 文本。失败后对同一来源最多自动视觉重试一次，且仅使用当前选中 provider；再次重试必须由用户显式点击。图像和文本不进入同步表或 Key 托管表。

## 接口

新增受保护端点 `/api/bookkeeping/deepseek-credential`：

- `GET`：读取当前账号的掩码状态。
- `PUT`：校验非空 API Key、加密覆盖保存，返回掩码状态。
- `POST`：使用当前已存 Key 发起无用户数据的最小连通性请求，返回脱敏验证结果。
- `DELETE`：物理删除当前账号的凭据。

识别与重新识别请求扩展非敏感字段 `provider: "DOUBAO" | "DEEPSEEK"`。DeepSeek 未配置、调用 401、超时和 JSON 无效分别返回稳定错误码。服务端绝不自动改用另一 provider。

## 验收

1. Vitest：用户 A/B 隔离、密文非明文、掩码、删除、未登录 401、解密只用于 provider 调用及错误不泄露 Key。
2. Vitest：`provider=DEEPSEEK` 使用 `deepseek-flash`，没有 Key 返回明确错误；豆包现有请求不回归。
3. Vitest：自由分类、长于四字的非空分类、旧三字段和新版层级合同均正确解析。
4. PostgreSQL 测试库：迁移可执行、唯一用户键有效、删除后不可读取或调用。
5. 部署前备份数据库与当前服务；生产仅用一次性测试账号和测试 Key 验证保存、删除、文本识别、一次视觉重试及账号隔离。真实用户 Key、OCR 原文和截图均不得出现在验收记录。

## 非目标

- 不为库存应用提供 DeepSeek Key 功能，不共享不同用户 Key，不支持明文下载/导出。
- 不改变用户主动触发识别、截图 30 天本地证据保留或云同步的边界。
- 不在本轮发布生产；部署须在自动化、测试库和备份证据齐备后另行确认。
